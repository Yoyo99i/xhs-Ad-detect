# 种草甄别 · xhs-Ad-detect

> 小红书笔记「软广/营销话术」风险检测工具 —— 参加 InfiniSynapse Vibe Coding 大赛作品

## 一、项目简介

「种草甄别」是一款面向普通用户的小红书笔记软广识别工具。用户粘贴一篇小红书笔记正文，系统从 **7 个维度** 自动扫描，输出一个**风险等级（可信度分 0–100）** 以及**每个维度的命中程度和加权贡献百分比**，帮助用户一眼判断「这篇是不是恰饭软广」。

核心理念不是"越严格越好"，而是 **宁漏不误伤**：真实的好物分享、个人经验打卡不应被误判为营销，只有"利益关联 + 营销意图"并存时才给高分。

## 二、核心功能

- **一键检测**：粘贴笔记正文 → 实时渲染风险结论、评分依据、维度明细、避坑小贴士。
- **7 维度加权评分**：推广未标明、利益未披露（软信号）、绝对化用语、隐性营销意图、功效夸张、信息可信度、情绪裹挟。
- **每维度可视化**：
  - 角标显示该维度**固定权重占比**（22% / 18% / 16% / 14% / 12% / 10% / 8%）。
  - 进度条在结果出来后显示该维度对本文的**加权贡献百分比**（系数 × 权重）。
- **严重程度分级**：轻 0.5 / 中 1.0 / 重 1.5（与知识库一致）。
- **结论双层级**：顶部 Hero 显示短版核心结论，下方摘要区显示完整判定依据，避免重复。

## 三、技术架构

```
前端 (public/index.html, 单文件无构建)
   │  POST /api/analyze  ──┐
   │                       │  后端 server.js (Node >=18, 零依赖)
   │  GET  /api/status      ├──▶  InfiniSynapse Agent (云端, 已绑定知识库)
   └───────────────────────┘        │
                                    ▼
                          知识库 Ad_risk_scoring_dimensions
                          (严重度系数 / 评分维度 / 宁漏不误伤铁律)
```

- **前端**：纯静态单文件 `public/index.html`，内联 CSS/JS，无构建步骤，可直接托管。
- **后端**：`server.js`，零依赖（仅 Node 原生 `http`/`fs`），负责：
  - 接收前端请求，通过 `POST /api/ai/message` 调用 InfiniSynapse 云端 Agent；
  - 异步任务 + 轮询，绕开部署平台免费版的请求超时；
  - 把**知识库铁律（宁漏不误伤 + F2 不单独命中）** 以最高优先级写死进每次请求的 system prompt，保证规则真正生效。
- **知识库**：在 InfiniSynapse 控制台绑定，Agent 自动检索；关键铁律同时内嵌进 `server.js` 以防向量检索遗漏。

## 四、评分维度（权重）

| 维度 | 权重 |
|---|---|
| 推广未标明 | 22% |
| 利益未披露（软信号） | 18% |
| 绝对化用语 | 16% |
| 隐性营销意图 | 14% |
| 功效夸张 | 12% |
| 信息可信度 | 10% |
| 情绪裹挟 | 8% |

加权公式：`单维贡献 = 严重程度系数(轻0.5 / 中1.0 / 重1.5) × 维度权重`，全部维度求和映射为 0–100 可信度分。

## 五、本地运行

```bash
# 1. 准备环境变量
cp .env.example .env
# 编辑 .env，填入真实 IS_API_KEY

# 2. 启动（零依赖，无需 npm install）
node server.js

# 3. 浏览器打开
# 前端是静态文件，可用任意静态服务器，例如：
python -m http.server 8099   # 然后访问 http://127.0.0.1:8099/public/index.html
```

> 注意：`server.js` 监听 `PORT`（默认 3000），前端通过 `fetch` 调用 `/api/analyze`。本地联调时前端与后端需同源或配置 `FRONTEND_ORIGIN`。

## 六、部署到 OnRender（示例）

1. 在 OnRender 新建 Web Service，连接本 GitHub 仓库。
2. Build Command：留空（零依赖）。Start Command：`node server.js`。
3. 环境变量：`IS_API_KEY=你的key`、`PORT=3000`。
4. 静态前端（`public/`）可由 OnRender 的 Static Site 或同一服务托管。
5. **每次修改 `server.js` 后需手动 Redeploy**，仅 push 不会让线上后端生效。

## 七、项目文件说明

| 文件 | 作用 |
|---|---|
| `server.js` | 后端转发服务，内嵌知识库铁律与评分系数 |
| `public/index.html` | 前端单页应用（核心交互与可视化） |
| `package.json` | 启动脚本 `npm start` → `node server.js` |
| `.env.example` | 环境变量模板（API Key / CORS 域名） |
| `infinisynapse_kb_content.md` | 知识库原文（评分维度、严重度系数、铁律） |
| `infinisynapse_*.html` / `*.md` | 方案文档、研究报告、合规审查等过程资料 |
